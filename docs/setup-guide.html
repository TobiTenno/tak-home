Setup guide

Walk through a Docker-first CloudTAK + TAK Server stack behind SWAG, optional T.Rex maps, then Authelia + LLDAP for SSO. Checkboxes stick in this browser.

What you get

NameUse
map.<domain>CloudTAK web (Let’s Encrypt via SWAG)
tiles.<domain>CloudTAK tiles / Hosted PMTiles
tak.<domain>ATAK (8089+) — TAK private CA, stream passthrough
auth.<domain>Authelia (+ optional /auth-admin/)
Two cert worlds. Map/tiles = SWAG LE. TAK ports = private CA. Never copy TAK *.pem / *.p12 into SWAG /config/keys. Leave tak out of Let’s Encrypt SUBDOMAINS.
browser │ HTTPS 443 ▼ SWAG ── map → tak_api:5000 ├── tiles → tak_tiles:5002 ├── auth → Authelia (+ /auth-admin) └── stream 8089/8443/… → tak_server (no decrypt) Authelia ← LDAP → LLDAP │ OIDC ▼ CloudTAK (+ TAK CoreConfig oauth for cert enroll)

1 · Copy & run setup

On the server, copy this tree next to your shared compose file, then:

./setup.sh example.com -f ../docker-compose.yml
# or
./setup.sh -h example.com --file ../docker-compose.yml
./setup.sh example.com -p opentopomap   # default map provider is trex

-f picks the compose file to include. Generated files land in tak-home/ beside that file. Include path is tak-home/compose.yaml.

Re-running setup rewrites hostnames and keeps secrets already in config/secrets.env and config/cloudtak.env.

    2 · Wire SWAG

    Stack publishes no host ports. Everything lives on Docker network tak.

    services:
  swag:
    networks:
      - tak
    ports:
      - "443:443"
      - "8089:8089"
      - "8443:8443"
      - "8446:8446"
      - "9001:9001"
networks:
  tak:
    name: tak

    Copy generated confs:

    FileSWAG path
    swag/cloudtak.conf/config/nginx/site-confs/
    swag/tak-stream.conf/config/nginx/stream-confs/ — not site-confs

    In SWAG nginx.conf, add a top-level stream block (sibling of http):

    stream {
    include /config/nginx/stream-confs/*.conf;
}
    docker exec swag nginx -t && docker exec swag nginx -s reload
# confirm stream ports listening, not only 443
docker exec swag netstat -tlnp | grep -E '443|8089|8443'
    Map vhost location / must proxy to tak_api.tak:5000 (or tak_api on the same network). /pmtiles/ → tak_pmtiles; tiles host → tak_tiles:5002.

    CSP for remote basemaps (T.Rex hillshade + Google) lives in config/cloudtak.env as NGINX_CSP_IMG_SRC / NGINX_CSP_CONNECT_SRC. Recreate tak_api after edits.

      3 · Bring up the stack

      From the directory that holds the compose file passed to -f:

      docker compose -f docker-compose.yml up -d tak_certs tak_database tak_server
docker compose -f docker-compose.yml cp \
  tak_server:/opt/tak/certs/files/root-ca.pem tak-home/tak-ca.pem
docker compose -f docker-compose.yml up -d \
  tak_certs tak_database tak_server tak_api tak_tiles tak_events \
  tak_retention tak_media tak_postgis tak_store tak_pmtiles
      --profile tak also starts every service with no profile. Prefer naming services as above.

      Smoke:

      curl -sk -o /dev/null -w '%{http_code}\n' https://map.example.com/api/server
# expect 401 without auth — means API is up through SWAG

        4 · Maps (T.Rex / Hosted)

        On the server, when the provider has a fetch.sh:

        ./maps/fetch.sh
./maps/fetch.sh --regions ks,mo,ar
./maps/fetch.sh --regions conus --elevation
./maps/fetch.sh --sprites-only

        Region ids: maps/providers/trex/regions.tsv. Sprites are proprietary / gitignored — local deploy only. 

        ./maps/render-basemap.sh --hosted \
  --tiles-host tiles.example.com --features ks-mo-features
./maps/publish-garage.sh
./maps/publish-garage.sh --as ks-mo-features features.pmtiles
        Hosted URL tile vars must be {$z}/{$x}/{$y} (dollar), not {z}. After Garage republish, script restarts tak_tiles so stale ETags do not 412/500. Protocol for Garage PMTiles in CloudTAK = hosted + vector (not a pmtiles enum).

          5 · ATAK enrollment

          After TAK is up, build a datapackage with the same DNS name on the cert:

          ./make-datapackage.sh tak.example.com

          Install the package in ATAK; trust the TAK private CA (not the LE cert).

            6 · Authelia + LLDAP SSO

            Goal: stop managing CloudTAK passwords by hand. Authelia = login / 2FA / OIDC. LLDAP = users & groups. Optional authelia-admin at https://auth.<domain>/auth-admin/ on the same host.

            6a · Directory + Authelia

            1. Run LLDAP on the tak (or shared) network; create base DN and an Authelia bind user.
            2. Run Authelia with authentication_backend.ldap.implementation: lldap.
            3. Point SWAG auth.<domain> at Authelia; proxy /auth-admin/ to authelia-admin if used.
            4. Enable Authelia OIDC provider; register confidential client cloudtak.
            # Authelia OIDC client (sketch)
identity_providers:
  oidc:
    clients:
      - client_id: 'cloudtak'
        client_name: 'CloudTAK'
        client_secret: '$pbkdf2-sha512$...'   # hashed secret
        public: false
        authorization_policy: 'two_factor'
        redirect_uris:
          - 'https://map.example.com/api/login/oidc/callback'
        scopes: ['openid', 'profile', 'email']
        grant_types: ['authorization_code']
        response_types: ['code']
        token_endpoint_auth_method: 'client_secret_basic'

            Discovery URL:

            https://auth.example.com/.well-known/openid-configuration

            6b · CloudTAK Admin → Login

            FieldValue
            Enable OIDC SSOon
            Enforce SSOoff until tested
            Provider Namee.g. Authelia
            OIDC Discovery URLAuthelia .well-known/openid-configuration
            Client ID / Secretmatch Authelia client (plaintext secret in CloudTAK)
            Redirect / Scopesleave blank for defaults
            IdP must return an email claim. CloudTAK username = email. Wrong email → wrong cert identity / groups.

            6c · TAK Server CoreConfig

            Needed so new SSO users can enroll a cert (CloudTAK presents the IdP token to TAK):

            <oauth usernameClaim="email">
  <openIdDiscoveryConfiguration
    name="cloudtak-sso"
    clientId="cloudtak"
    secret="SAME_PLAINTEXT_SECRET"
    redirectUri="https://map.example.com/api/login/oidc/callback"
    configurationUri="https://auth.example.com/.well-known/openid-configuration"/>
</oauth>

            Restart tak_server after. TAK must reach Authelia discovery; document must include scopes_supported.

            Do not rely on Authelia forward-auth alone for CloudTAK — that only gates nginx; CloudTAK still needs its own OIDC session. ATAK keeps using client certs; Authelia does not replace 8089 cookies.

            Official notes: CloudTAK OIDC, Authelia ↔ LLDAP. Auth is a separate stack from tak-home (LLDAP/Authelia not in this compose). Plan: docs/AUTH-PLAN.md. Move checklist: docs/DEV-MOVE.md.

            Other apps

            Same auth stack can add more OIDC clients for other services. Register client, redirect URI, scopes per that app’s docs; gate with an Authelia group/policy. Prefer the app’s native OIDC over forward-auth alone when it has its own session.

              7 · Migrate existing users

              ThingMigrate?
              Emails / usernames (CloudTAK profiles)Yes → LLDAP uid + mail
              Groups / display namesYes
              CloudTAK certs, overlays, dataStay in CloudTAK DB
              PasswordsNo — LLDAP uses OPAQUE; reset once
              Existing ATAK client certsKeep working
              1. Export CloudTAK usernames/emails from Postgres profiles.
              2. Create matching LLDAP users (mail identical).
              3. Temp password or invite / reset flow.
              4. Test OIDC with enforce off; same email → existing CloudTAK profile.
              5. Then set oidc::enforced.
              Locked out after enforce? Admin token PUT /api/config with {"oidc::enforced": false}, or delete that settings row in the CloudTAK DB.
