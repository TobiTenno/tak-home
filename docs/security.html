Security reminders

This is not a full hardening audit. It is a short checklist for operators running tak-home / auth-home on a self-hosted box, plus links to guides that already do the deep work well.

Start with established guidance

Read (and periodically revisit) at least one of these:

Guide Why
NIST SP 800-190 — Application Container Security Guide Vendor-neutral container threat model and controls
CIS Docker Benchmark Prescriptive host / daemon / runtime / image checks (CIS membership or purchase for the full PDF; many tools implement the controls)
Docker Engine security Official Docker security overview and feature docs
CISA — Cybersecurity Best Practices General org/host hygiene (patching, MFA, backups, logging)

If the Docker host is Linux, also apply a host benchmark (for example CIS Ubuntu or your distro’s equivalent) before worrying about fancy container flags.

Stack-specific reminders

Network & certificates

  • Keep two certificate worlds separate: SWAG/Let’s Encrypt for map / tiles / auth; TAK private CA for ATAK ports. Do not drop TAK *.pem / *.p12 into SWAG /config/keys.
  • Leave tak out of Let’s Encrypt SUBDOMAINS. Stream-proxy TAK ports without terminating TLS on SWAG.
  • Prefer publishing only what SWAG needs on the host (443 + TAK stream ports). Do not publish LLDAP/Authelia admin ports unless you deliberately used --no-swag.

Auth & admin surfaces

  • Run Authelia/LLDAP from auth-home, not inside the TAK profile lifecycle.
  • Keep Authelia login reachable for SSO; lock admin UIs (/auth-admin/, LLDAP UI) with --admin-expose (subnet, localhost, or tailscale — avoid public unless you accept the risk).
  • Leave CloudTAK Enforce SSO off until login works. Keep a break-glass path (oidc::enforced false via admin API or DB) documented offline.
  • Treat config/secrets.env, config/cloudtak.env, config/authelia.secrets.env, and OIDC client secrets as credentials: mode 600, never commit, rotate if leaked.

Data & maps

  • Garage and PostGIS hold operational data — include them in backup/restore drills, not only Compose YAML.
  • T.REX sprites are proprietary local assets; do not publish maps/data/sprites/ to a public git remote.
  • CSP (NGINX_CSP_*) is allowlisting remote tile hosts. Adding wildcards or overly broad hosts weakens XSS defenses in the map UI.

Updates & supply chain

  • Pin or knowingly float image tags; re-read release notes for TAK Server, CloudTAK, Authelia, and LLDAP before upgrading.
  • Pull images from the vendors listed on the references page; avoid unmarked mirrors.
  • After upgrades, re-test SSO, ATAK enroll, and map paint before calling the host “done.”

Logging & access

  • Restrict SSH (keys only, no password root login, optional Tailscale/bastion).
  • Keep SWAG and Docker logs somewhere you will actually look (disk rotation or remote syslog).
  • Limit who can run docker / docker compose on the host — that group is effectively root.

When something looks wrong

  1. Confirm you are on the intended Compose project and network (tak / auth).
  2. Check SWAG nginx -t and access/error logs before rebuilding app containers.
  3. For SSO lockouts, disable enforce first, then fix IdP claims (email required for CloudTAK).

Questions about why auth is a separate stack live in the auth plan. Operator steps are in the setup guide.
